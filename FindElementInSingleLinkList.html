Case 1 Approach: No Recursive

  1. Start with a pointer at the head of the list.
  2. Compare the current node value with the target.
  3. If it matches, return that node.
  4. If it does not match, move the pointer to current.next.
  5. If the pointer becomes null, the value is not in the list.

Case 2 Approach: Recursive

  1. Call the function with the head node.
  2. If the node is null, stop and return not found.
  3. If the node value equals the target, stop and return that node.
  4. Otherwise call the same function on node.next.
  5. Each call waits for the next call to return.

Running Time Compare

Both procedures check at most every node once, so both are O(N) time. Iterative search uses O(1) extra space. Recursive search uses O(N) call-stack space in the worst case.

When Does Recursion Terminate?

Recursive search terminates when it finds the target or reaches null after the last node. For a list with N nodes, it makes at most N + 1 calls. In real browsers, very large lists can overflow the call stack; the safe size depends on the JavaScript engine, but thousands to tens of thousands of recursive calls can be risky. Iteration is safer for very large lists.
